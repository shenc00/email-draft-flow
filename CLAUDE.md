# email-draft-flow — Project Rules

Compress large outputs via Headroom before reasoning over them.

## Workflow
1. Read STATUS.md before starting.
2. Present task list. Wait for approval (Proceed/Execute/Approved/Run it/Go) before writing code, files, or running commands. Approval holds until scope changes.
3. One task at a time. Stay within approved scope — no inferred extra work; pause if scope changes.
4. State assumptions explicitly. Report risks/blockers immediately.
5. Validate each task (verify, test, review) before marking done. Document failures — do not commit failed work.
6. Update STATUS.md after each completed task.
7. Never delete files without explicit confirmation.

## Git
Pass: update STATUS.md → add → commit → push → report hash.
Fail: document issue → no commit → no push → report.
Never force push.

## Precedence
Headroom > Strategic Planning > Task Decomposition > Caveman > Scope Lock > Ponytail

Concise, non-repetitive responses.
